# Splitter MVP 2.0 — BYN, корзина, доли в рублях и QR

Это интерактивный прототип оплаты общего заказа пиццы в белорусских рублях. В **QR-режиме решения с настоящих телефонов синхронизируются с инициатором через локальный сервер**, но никакие банковские операции не проводятся.

## Самый простой способ запуска (Windows)

1. Распакуйте ZIP-архив в обычную папку (не запускайте файлы прямо внутри ZIP).
2. Установите [Python 3.10+](https://www.python.org/downloads/) с опцией **Add Python to PATH**, если его ещё нет.
3. Двойным щелчком запустите `start_windows.bat`. При первом запуске потребуется интернет для установки небольшой библиотеки QR.
4. На компьютере откроется `http://localhost:8765`. Если вкладка не открылась, введите этот адрес сами.
5. Соберите свою корзину, выберите Splitter, укажите доли и создайте запросы. Возле каждого друга нажмите **«Показать QR»**.
6. Откройте QR на телефоне друга (камера → QR). На телефоне друга появятся его сумма и две кнопки: **«Согласен оплатить»** или **«Отклонить запрос»**. При подтверждении он должен видеть адрес сервера.
7. Инициатор увидит статус через ~2 секунды без перезагрузки. Если хотя бы один человек отклонил запрос или смоделировал нехватку денег, весь заказ отменяется.

**Важно для QR:** компьютер и телефон должны быть в одной доступной локальной сети Wi-Fi, а Windows Firewall должен разрешить входящие подключения к порту `8765` для Python. В командной строке показывается **ссылка для телефона** вида `http://192.168.1.25:8765`. Если телефон не может её открыть, QR тоже не заработает. На открытой/публичной сети не используйте настоящие телефоны и номера карт.

## Альтернативный запуск (macOS, Linux, Windows)

```bash
python -m pip install -r requirements.txt
python server.py --host 0.0.0.0 --port 8765
```

Для запуска в публичном интернете нужен собственный HTTPS-домен и развёрнутый сервер. Передайте реальный адрес для QR:

```bash
python server.py --port 8765 --public-url https://example.com
```

В этом случае домен должен быть реально настроен на сервер (reverse proxy с HTTPS); параметр сам по себе **не публикует** приложение в интернете. Не выкладывайте этот демо-сервер в публичный доступ без дополнительной авторизации, защиты и проверки безопасности.

### Прототип одним файлом без сервера

`index.html` можно открыть двойным щелчком. В таком режиме работают меню, корзина, BYN, смена «Рубли/Проценты», деление поровну, добавление друзей, локальные подтверждения с тестовым PIN `1234`, отказ, нехватка средств и чек. **QR и обмен статусами между телефонами НЕ работают без сервера**, о чём приложение прямо сообщает.

## Реализовано

- Меню из 8 позиций; добавить/убавить количество, собрать любой заказ, увидеть стоимость товаров и доставки. Демонстрационные цены указаны в **BYN**. Доставка 4,90 BYN, бесплатная от 60,00 BYN.
- Участники по умолчанию: инициатор, Маша, Илья (две *примерные* записи). При открытии деления счёт делится **поровну между всеми**, с распределением остатка до копейки. Можно добавлять до 8 друзей или удалять примеры.
- Вкладки **«В рублях»** / **«В %»**. После ручного ввода конкретная доля фиксируется, а остаток автоматически поровну распределяется между участниками без закреплённых долей. Кнопка «↻ Разделить поровну» снимает фиксации. Сумма всех долей всегда точно равна полной сумме заказа.
- Демо-добавление друзей по телефону или номеру карты. Исходные номера не передаются на сервер; передаются только последние 4 цифры в маскированной подписи. **Автоматического поиска владельца карты, SMS и push нет.**
- При запуске сервера каждому другу выдаётся отдельный секретный URL + QR. QR можно показать рядом или переслать ссылку. Друг подтверждает/отклоняет с собственного устройства; ответ сохраняется на сервере (SQLite) и поступает инициатору при обновлении статусов.
- У друга есть дополнительная кнопка «Смоделировать нехватку средств». Вся демо-операция отклоняется при отказе, нехватке денег или тайм-ауте в **15 минут**.
- На экране инициатора сохраняется прежний локальный способ имитации Face ID, отпечатка и PIN-кода `1234`. Настоящей биометрической/банковской идентификации нет.
- При одобрении всеми на сервере симулируется сценарий «друзья → инициатор → ресторан». Реального списания нет, в SQLite одним действием меняется состояние сеанса.
- После перезагрузки вкладки при работе с сервером восстанавливается активный сеанс в том же браузере (через `sessionStorage`).

## Что нужно знать об ограничениях

- **Это MVP для проверки UX и согласия друзей, не сервис для платежей.** Ссылка QR — bearer token. Любой, кто получил её, может ответить от имени друга. Нельзя считать этот ответ юридически или банковски аутентифицированным.
- В исходных данных цены и тестовые остатки вымышлены. Настоящие номера карт/личную информацию использовать не нужно.
- **Никаких SMS, push, реальной проверки средств, 3-D Secure, WebAuthn, банковского Face ID, переводов или платежей ресторану нет.** Имеется только серверная фиксация тестовых ответов настоящих пользователей.
- Для платежной версии нужен лицензированный PSP/банк с токенизацией и аутентификацией плательщиков, резервированием/авторизацией каждой доли, идемпотентным захватом суммы, компенсациями/возвратами, журналами, антифродом и согласием ресторана. Путь денег через личный счёт инициатора требует отдельной правовой оценки и может быть заменён расчётами через регулируемого провайдера.
- Сервер рассчитан только на демонстрации. Нет учётных записей, bank-grade auth, TLS, rate limiting, полноценного anti-CSRF и мониторинга. На публичный хостинг без доработки не разворачивать.

## Структура

- `index.html` — интерфейс инициатора, работает офлайн в упрощённом демо.
- `friend.html` — страница подтверждения на телефоне.
- `server.py` — API, SQLite, создание QR-кодов, статусы в реальном времени через опрос каждые ~2 секунды.
- `requirements.txt` — генератор QR.
- `start_windows.bat` — запуск в Windows.
- `test_server.py` — тесты расчётов и сценариев подтверждения.

## API для разработчика

`POST /api/sessions` — создать запрос с корзиной и суммами долей (сервер считает стоимость сам, без доверия к сумме от клиента). `GET /api/sessions/{ownerToken}` — состояние инициатора. `GET /api/invite/{inviteToken}` — экран друга. `POST /api/invite/{inviteToken}/respond` с `{ "decision": "approve" | "reject" | "insufficient" }`. `GET /api/qr/{inviteToken}` — персональный PNG QR. `POST /api/sessions/{ownerToken}/cancel` — отмена инициатором.

Доли хранятся как целые **копейки** (`amount_cents`), а не числа с плавающей точкой.
